## 候选对比

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **pynput** | 维护活跃、跨平台；键盘/鼠标/全局热键一套 API 全覆盖；回调线程模型清晰 | 低级钩子理论上可能被部分杀软启发式关注（见风险） | ✅ 采用 |
| keyboard | API 简单 | 键盘为主，鼠标监听要另拼方案；全局热键有版本差异 | 备选 |
| pywin32 原生 SetWindowsHookEx | 零第三方依赖 | 需自建消息泵线程 + 大量样板代码，维护成本高 | 弃 |

## 实测数据（2026-10-24，本机 i7/32 逻辑核/Win11）

| 指标 | 数值 | 预算 |
|---|---|---|
| 挂载三监听后空闲 CPU | **0.0%**（单核口径，30s 冒烟） | — |
| 含感知层的常驻内存 | **51 MB** | <150MB ✅ |
| 聚合器单事件处理成本 | **0.48 µs**（10 万次合成事件实测，含 feed+poll） | <20µs ✅ |
| 前台窗口轮询（4Hz ctypes） | 可忽略（每次数个 win32 调用） | — |

架构决定：pynput 回调运行在监听线程，**回调里只入队/写时间戳**，Qt 侧 4Hz 定时器统一消费——跨线程只传不可变数据，杜绝竞态；鼠标移动不进队列（只更新时间戳），避免高频事件刷爆队列。

## 风险与白名单指引（R1 跟踪）

- pynput 属"具备键盘记录能力"的库，部分杀软启发式可能对 `pythonw.exe + pynput` 组合提示；本环境无法安装主流杀软逐一实测。
- 已做的自证清白设计：事件**只在内存**计算、无任何落盘/网络行为（PRD 铁律），代码可审计。
- 用户若遇误报：将 `缘缘桌宠` 项目文件夹加入杀软白名单即可；此指引将写入 M5 用户文档。
- 后备方案：如某杀软强杀，可退回 pywin32 自建钩子（行为等价，工作量约 1 天）。
